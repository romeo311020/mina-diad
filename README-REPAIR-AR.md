# منصة مستر مينا دياب — نسخة الإصلاح

## تم إصلاحه
- استعادة تنسيق صفحة التواصل، الحقول، الأزرار وأيقونات WhatsApp وInstagram.
- إصلاح حدث استمارة التواصل؛ النموذج يفتح WhatsApp برسالة تتضمن الاسم والمرحلة ونوع الاستفسار والرسالة.
- الإبقاء على روابط التواصل الأصلية ورابط ملف المطور.
- إصلاح تسجيل الطالب بحيث يحاول إنشاء ملف profiles عند أول دخول إذا لم يكن موجودًا، مع رسائل أخطاء مفهومة.
- إضافة ملف admin.js المفقود وملف setup.sql المستخدم للوحة الإدارة.
- الحفاظ على تصميم الأبيض والذهبي ومربع الحساب الزجاجي في الصفحة الرئيسية.

## الإعدادات
`supabase-config.js` يحتوي على Project URL والمفتاح العام Publishable الذي وفره صاحب المشروع. المفتاح العام مناسب للواجهة بشرط أن تكون سياسات RLS صحيحة. لا تضف service_role أو secret key إلى الموقع.

## النشر بدون حذف الملفات القديمة
1. فك ضغط الملف.
2. ارفع الملفات الجديدة/المعدلة إلى جذر المستودع `romeo311020/mina-diad` مع اختيار **Add file / Upload files**، ولا تحذف مجلد `images` الموجود في مستودعك.
3. احتفظ بصورة `images/mina-diab.jpg` الموجودة بالفعل في المستودع. الأرشيف لا يستبدل الصورة الأصلية.
4. انتظر اكتمال GitHub Pages ثم افتح الموقع في نافذة خاصة أو اعمل تحديثًا قويًا.

## Supabase — ما تم التحقق منه وما لم يتم
- تم التحقق من أن صيغة ملف الإعدادات تحتوي على Project URL ومفتاح `sb_publishable_` العام، وأن الرابط يطابق المشروع الذي قدمه المستخدم.
- لم يمكن إجراء اختبار دخول فعلي على حساب Supabase الخاص بك من هنا؛ لا يمكن تأكيد حالة Authentication أو سياسات RLS أو بيانات الطلاب دون اختبار من لوحة مشروعك.
- في Supabase > Authentication > Providers، تأكد من تفعيل Email.
- إذا كان Confirm email مفعّلًا، افتح رسالة التأكيد قبل تسجيل الدخول.
- شغّل `setup.sql` مرة واحدة لإعداد `site_settings`.
- لا تشغّل ملف سياسات `auth-profiles-policies.sql` عشوائيًا قبل مراجعة السياسات الحالية؛ سياسات RLS permissive قد تتجمع بمنطق OR. استخدمه بعد مراجعة سياسات `profiles` الموجودة.
- لوحة الإدارة تحتاج حساب Auth موجودًا وصفًا في `public.profiles` مع `role = 'admin'`. لا تجعل التسجيل العام يمنح صلاحية admin.
